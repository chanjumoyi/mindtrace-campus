# 心迹AI需求清单

版本：v0.1
基线：2026 年 6 月《心迹AI——大学生心理健康智能交互平台立项报告》
状态口径：**已有**＝当前代码具备可运行实现；**部分**＝只有接口、算法、素材或占位页面；**未开始**＝仓库中没有可验收实现。

## 1. 当前结论

当前仓库已完成 Vue 3 + FastAPI + MySQL 的基础骨架，具备情绪记录、电子手账 API、Mock 对话、安全提示和笔迹特征分析原型。它尚未达到立项报告所述“完整可运行平台”的预期成果，最主要缺口是账号与授权、真实 LLM 对话、前端完整业务闭环、多模态评估、数据安全、用户研究和效果评估。

## 2. P0：核心平台与安全底座

| ID | 需求 | 当前状态 | 验收标准 |
|---|---|---|---|
| P0-01 | 用户注册、登录、退出和会话管理 | 未开始 | 密码安全哈希；受保护接口拒绝匿名访问；具备登录/退出自动化测试 |
| P0-02 | 用户数据归属与访问控制 | 未开始 | 手账、情绪和分析记录均绑定用户；用户不能读取或修改他人数据 |
| P0-03 | 电子手账完整闭环 | 部分 | 前端可新增、查看、编辑、删除手账；后端支持分页与归属校验 |
| P0-04 | 情绪/压力日常记录与趋势 | 部分 | 可记录、查询和删除；前端展示至少 7/30 日趋势，处理空数据和失败状态 |
| P0-05 | AI 支持性对话 | 部分 | 接入经配置的 DeepSeek 或兼容 LLM；支持多轮上下文、超时降级、免责声明和调用审计；无密钥时安全回退 |
| P0-06 | 危机识别与转介流程 | 部分 | 覆盖自伤、伤人和紧迫风险测试集；显示明确的本地求助路径；高风险事件最小化记录并支持人工复核 |
| P0-07 | 知情同意与隐私设置 | 未开始 | 首次使用前展示用途、范围和风险；可撤回授权、导出和删除个人数据 |
| P0-08 | 敏感数据保护 | 未开始 | 传输加密；敏感字段加密或脱敏；身份映射与研究数据隔离；日志不记录正文和密钥 |
| P0-09 | 数据库迁移与备份恢复 | 未开始 | 使用迁移工具管理 Schema；完成一次备份恢复演练；禁止生产环境启动时自动建表 |
| P0-10 | 基础质量门禁 | 部分 | 后端测试、前端构建、格式/静态检查在 CI 中自动执行，主分支失败时禁止合并 |

## 3. P1：立项核心功能

| ID | 需求 | 当前状态 | 验收标准 |
|---|---|---|---|
| P1-01 | Canvas 笔迹采集 | 部分 | 前端采集坐标、时间、停顿、速度、压力/倾角（设备支持时）；完成设备兼容性与授权提示 |
| P1-02 | 笔迹行为特征与纵向反馈 | 部分 | 现有特征服务接入产品页；结果只描述行为；展示置信度、局限和历史对比；测试异常输入 |
| P1-03 | 多源数据统一表征 | 未开始 | 对话、手账、情绪和笔迹使用统一时间线/用户标识；定义版本化特征 Schema 和缺失值策略 |
| P1-04 | 多模态情绪辅助评估 | 未开始 | 明确训练/验证数据、标签来源和指标；输出可解释依据与不确定性；不得作为诊断或危机唯一依据 |
| P1-05 | 冥想与瑜伽跟练 | 部分 | 至少提供可播放、可暂停、可完成的内容；记录用户授权下的完成情况；内容经过专业审核 |
| P1-06 | 每周心理健康科普 | 部分 | 内容具备来源、审核人、发布日期和版本；前端支持列表、详情与已读状态 |
| P1-07 | 个性化内容推荐 | 未开始 | 推荐依据可解释、可关闭；冷启动和无数据场景可用；不使用敏感推断做强制推荐 |
| P1-08 | 房树人辅助观察 | 部分 | 完成绘图/上传、结构化问卷、可观察元素提取、探索性提问和人工复核；无诊断性输出 |
| P1-09 | AI 辅助心理沙盘 | 部分 | 使用现有素材完成摆放、保存、结构化分析和回看；Prompt 注入与诊断越界测试通过 |
| P1-10 | 管理与内容审核 | 未开始 | 管理员可管理科普/练习内容、审核 AI 规则版本、查看匿名化运行指标；操作可审计 |

## 5. 非功能需求

| ID | 类别 | 验收标准 |
|---|---|---|
| NFR-01 | 可用性 | 桌面端和移动端核心流程可完成；加载、空状态、错误和重试提示完整 |
| NFR-02 | 可访问性 | 键盘可操作；表单有标签；颜色对比满足 WCAG 2.1 AA 的关键要求 |
| NFR-03 | 性能 | 约定测试环境下，普通 API P95 小于 500 ms（不含外部 LLM）；首屏资源和慢查询有监控 |
| NFR-04 | 可靠性 | 外部 LLM、数据库或内容服务失败时可降级；关键写入幂等或防重复提交 |
| NFR-05 | 安全 | 通过依赖、密钥、越权、注入、XSS/CSRF 和上传文件检查；高危问题上线前清零 |
| NFR-06 | 可维护性 | API/Schema 版本化；关键模块有测试；公共函数、配置和错误码不重复散落 |
| NFR-07 | 可观测性 | 健康检查、结构化日志、请求 ID、错误指标齐全，且不记录敏感正文 |

## 6. 建议实施顺序

1. **2026.08—2026.09：安全底座。** 完成 P0-01、P0-02、P0-07、P0-08、P0-09、P0-10。
2. **2026.09—2026.12：核心闭环。** 完成 P0-03 至 P0-06，并把 P1-01、P1-02 接入前端。
3. **2026.12—2027.02：辅助模块。** 完成 P1-03 至 P1-10，重点进行专业审核和安全评测。
4. **2027.02—2027.05：研究与结项。** 完成 P2 系列，依据真实测试结果迭代，不以功能数量替代有效性证据。

## 7. 范围约束

- 平台定位为心理健康教育、日常支持和自我觉察工具，不提供医学诊断或替代紧急服务。
- PHQ-9、GAD-7、PSS、笔迹、房树人和沙盘结果均不能单独作为个体诊断或处分依据。
- 在伦理审批、知情同意、数据管理方案和专业审核完成前，不采集真实参与者敏感数据。
- 真实联系方式、身份信息、对话、笔迹、量表结果和 API 密钥不得进入 Git 仓库。
