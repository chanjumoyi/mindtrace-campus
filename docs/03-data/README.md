# 数据模型与隐私约束

状态：已按立项报告对齐
最后更新：2026-10-12

真人笔迹研究、数位板设备验证、量表时间点、轨迹字段、质量规则、公开数据集和训练权重，以[《笔迹数据集与数位板采集规范》](./handwriting-collection-and-dataset-spec.md)为执行基线。编写采集程序或下载研究数据前应先完成其中的准备清单。

## 核心实体

| 实体 | 用途 | 关键约束 |
| --- | --- | --- |
| User | 用户账号与隐私设置 | 密码安全哈希；敏感身份信息最小化 |
| ConsentRecord | 知情同意与授权版本 | 记录版本、范围、时间和撤回状态 |
| MoodEntry | 心情、压力、睡眠和备注 | 属于 User；支持删除和趋势统计 |
| JournalEntry | 电子手账 | 属于 User；正文按敏感数据处理 |
| ChatSession / ChatMessage | AI 对话上下文 | 属于 User；正文不得进入普通日志 |
| HandwritingSession | 笔迹任务、设备和轨迹元数据 | 原始轨迹与派生特征分离 |
| AnalysisRecord | 模型输入摘要、版本和结构化结果 | 保存依据、置信度、局限和降级状态 |
| HtpRecord | 房树人绘画、问卷和观察结果 | 不保存诊断性标签 |
| SandplayRecord | 沙盘元素、位置和观察结果 | 保留素材与规则版本 |
| WellnessContent | 冥想、瑜伽和科普内容 | 记录来源、审核、发布日期和版本 |
| ContentProgress | 用户完成或已读状态 | 属于 User，可撤回个性化使用授权 |
| AuditLog | 安全相关操作和模型调用审计 | 不记录敏感正文或密钥 |

## 数据分区

- 业务库保存账号、授权、手账、情绪、内容进度和必要的分析记录。
- 原始轨迹、绘画、沙盘快照和导出包通过对象存储接口保存；MySQL 只保存对象键、哈希、所有者和生命周期元数据。
- 开发环境使用本地文件适配器，集成和用户测试环境使用 S3 兼容适配器，业务模块不得感知具体存储供应商。
- Redis 只传递后台任务消息，不作为业务事实来源或最终任务状态存储。
- 研究数据使用去标识化参与者编号，与账号身份映射隔离保存。
- 原始笔迹、绘画、量表和对话只在研究方案明确需要时采集。
- 测试和演示数据必须为合成数据或充分匿名的数据。

## 数据约束

- 所有时间使用明确时区，并通过 ISO 8601 对外传输。
- 枚举、Schema、特征和模型均需版本化。
- 删除用户时应覆盖业务记录、对象存储和可识别的研究映射。
- 生产环境使用数据库迁移，禁止依赖启动时自动建表。
- 每个分析结果记录 Schema、特征、模型、Prompt 和安全策略版本。
- `.env`、数据库文件、真实参与者数据和 API 密钥不得提交 Git。

具体的数据分类、事务规则、对象键和删除要求以[系统架构说明](../02-architecture/README.md)为准。

## 研究与伦理要求

- 用户调研或效果评估开始前完成伦理审查和知情同意。
- PHQ-9、GAD-7、PSS 等量表须核实使用条件，由专业人员把关。
- 量表分数、笔迹、房树人和沙盘结果不能单独用于诊断、处分或危机判定。
