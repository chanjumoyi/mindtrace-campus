# AI 与多模态分析设计

状态：已按立项报告对齐
最后更新：2026-10-11

## 技术方案

- 对话与自然语言解释通过 DeepSeek 或兼容 OpenAI 协议的 LLM API 提供。
- 所有模型调用必须经过统一 `LlmGateway`；业务模块不得读取供应商密钥、拼接供应商 URL 或直接解析供应商响应。
- 无密钥、超时、限流或输出不合规时，返回确定性的本地降级结果。
- 笔迹使用本地特征提取算法处理坐标、时间、速度、停顿、压力和倾角。
- 多模态研究在文本和笔迹特征上建立版本化表征，先完成离线基线和误差分析，再评估是否进入产品反馈。
- 房树人和沙盘使用结构化问卷、对象/几何特征和可观察元素生成探索性问题。

## 输出契约

分析结果至少包含：

```json
{
  "status": "SUCCESS",
  "summary": "非诊断性的客观摘要",
  "evidence": [],
  "confidence": 0.62,
  "limitations": [],
  "exploration_questions": [],
  "model_version": "model-name@version",
  "prompt_version": "prompt-name@version"
}
```

## 安全边界

- 不输出医学诊断、人格定性或确定性的心理状态结论。
- 不把笔迹、绘画、沙盘或单一量表作为危机识别的唯一依据。
- 对自伤、伤人或紧迫危险表达提供明确求助路径，并建议专业人员复核。
- Prompt、知识库、工具参数、规则和模型均需版本化并可审计。
- 发送给外部 LLM 的内容必须最小化、去标识化，并遵循用户授权范围。
- 不在普通日志中保存对话、手账、量表、图像或原始轨迹。

## 评估要求

- 预先定义训练集、验证集、测试集和数据泄漏防护策略。
- 报告准确率、精确率、召回率、F1、校准度和分组误差等适用指标。
- 保留简单基线，与文本单模态、笔迹单模态和融合模型进行对比。
- 建立越界输出、Prompt 注入、虚假确定性、危机表达和隐私泄漏测试集。
- 用户效果评估与模型准确率评估分开，避免把相关性表述为因果结论。

LLM 网关、任务适配器、版本字段和安全处理流水线以[系统架构说明](../02-architecture/README.md)为准。
