# MindTrace Campus：从零开始的完整模型训练与迁移学习方案

方案版本 V1.0 · 2026 年 10 月 23 日 · 适用于中期开发至最终结题

我建议你们现在正式确定一条技术路线，并围绕它开展后续全部工作，不再因为发现一个新的开源模型就反复推翻方案。

最终确定的路线是：CASIA-onDo 自监督预训练 → EMOTHAW 有监督训练 → MindTrace 中文数据迁移与验证。

这个方案能够同时满足你们的三个目标：

1. 真正训练一个深度学习模型，而不是仅仅调用现成 API。
2. 重点分析笔速、笔压、轨迹方向、书写大小、停顿、笔画形态等信息，而不是识别文字。
3. 最大限度利用公开数据，缓解 MindTrace 只有约 20 名参与者、每人 3 次测量的数据不足问题。

但要明确：这是一套可以固定执行的研究实验方案，不是已经被证明能够准确预测心理状态的产品方案。 我们能提前固定模型结构、数据流、训练方法、评价指标和备选路径，但无法保证最终预测准确率。

## 一、最终选定的模型架构

阶段 A：CASIA-onDo

中英文笔迹轨迹，无心理状态标签

自监督预训练：遮盖部分书写轨迹 → 预测被遮盖的数据

笔迹动态编码器：BiGRU

学习速度、轨迹、时间、笔压、笔画状态的时序表示

阶段 B：EMOTHAW

数字笔迹 + DASS 抑郁、焦虑、压力问卷标签

监督训练：先冻结编码器，再尝试局部微调

心理问卷指标预测模型

预训练编码器 + 统计特征融合 + 监督预测头

阶段 C：MindTrace

自采中文笔迹 + 自有问卷参考标签

替换目标预测头，使用自采数据适配与独立验证

最终模型评价与结果程序集成

特征分析 · 问卷参考指标 · 不确定性 · 纵向变化

这三个阶段对应两种不同的模型训练方法。

| 阶段 | 数据       | 训练方式             | 模型学到什么                 |
| ---- | ---------- | -------------------- | ---------------------------- |
| A    | CASIA-onDo | 自监督预训练         | 通用书写运动规律             |
| B    | EMOTHAW    | 有监督学习、局部微调 | 与 DASS 指标有关的统计规律   |
| C    | MindTrace  | 迁移学习、预测头训练 | 对你们自定义问卷指标进行适配 |

这里最重要的是：阶段 B 和 C 的心理问卷不相同，所以阶段 C 不能直接沿用 EMOTHAW 的预测头。 我们主要复用编码器中的参数，然后训练新的目标预测头。

本路线参考了 POSM 笔迹自监督研究和 EMOTHAW 相关心理状态分类研究，但这个特定的三阶段组合仍需要你们自己验证。

## 二、先固定技术选型，后续不再频繁换模型

| 模块         | 固定技术方案                          | 作用                      |
| ------------ | ------------------------------------- | ------------------------- |
| 主要编程语言 | Python 3.10                           | 数据处理与训练            |
| 深度学习框架 | PyTorch                               | 神经网络训练              |
| 数据处理     | NumPy、Pandas、SciPy                  | 清洗和特征计算            |
| 传统机器学习 | scikit-learn                          | Ridge、Random Forest 基线 |
| 神经网络主干 | 双向 GRU（BiGRU）                     | 动态笔迹序列编码          |
| 自监督方式   | Masked Trajectory Reconstruction      | 恢复被遮盖的轨迹          |
| 监督训练     | 小型预测头 + 可选局部微调             | 学习问卷标签              |
| 实验管理     | CSV + JSON 日志，后续可用 TensorBoard | 保存和比较实验            |
| 模型保存     | `.pt` / `.pth`                        | 模型权重                  |
| 结果程序集成 | Python 推理 API                       | 提供结构化结果            |

选择 BiGRU 而不是直接选择大型 Transformer，主要是出于数据规模和工程可控性。

你们没有上万名参与者的心理状态标签。使用参数量很大的 Transformer，不一定带来更好结果，反而可能加剧过拟合。

BiGRU 本身也是深度学习神经网络，完全可以进行预训练、迁移学习和微调。

未来如果希望与 Transformer 比较，可以作为独立实验；但不建议现在就把更换模型结构设为必经步骤。

### 3.3 现在就把心理预测目标固定下来

根据你此前提供的 JSON，MindTrace 使用 `MINDTRACE_RECENT_STATE_18`，其中有 16 道症状相关题目和 2 道日常功能影响题目。

为了避免训练过程中随意更换目标，我建议：

| 目标         | 具体定义                                    | 使用方式               |
| ------------ | ------------------------------------------- | ---------------------- |
| 主要目标     | `symptomSumS`，16 道题的计分总和，范围 0–64 | 回归实验               |
| 次要目标     | 心境、担忧、压力、睡眠精力注意等维度分数    | 解释性分析、探索性预测 |
| 纵向目标     | 同一参与者不同月份的分数差值                | 变化关联分析           |
| EMOTHAW 目标 | DASS 定义的抑郁、焦虑、压力类别             | 公开数据监督训练       |

因此，最终不是要让模型输出一个含义不清楚的“心理健康百分比”，而是先研究它能否预测明确的问卷参考指标。

要强调：MRS-18 的 `symptomSumS` 是你们项目自定义指标，不能未经验证就称为临床心理状态或疾病严重程度。

### 4.2 三个数据集必须转换成统一格式

这一步我建议只编写一次通用接口，之后所有模型都使用它。

例如统一每条书写任务的表示：

```
{    "dataset": "mindtrace",    "participant_id": "anonymous_id",    "session_id": "session_001",    "task_id": "copy_sentence",    "device_id": "device_type",    "trajectory": [        # dx, dy, dt, pressure, pen_state    ],    "feature_mask": [],    "label": None,    "quality": "usable"}
```

其中 `trajectory` 最初由原始坐标和时间戳计算得到。

建议先固定五个通道：

\[ X_t=[\Delta x_t,\Delta y_t,\Delta t_t,p_t,s_t] \]

含义如下：

| 通道         | 含义         | 来源           |
| ------------ | ------------ | -------------- |
| \(\Delta x\) | 水平坐标变化 | 相邻 x         |
| \(\Delta y\) | 垂直坐标变化 | 相邻 y         |
| \(\Delta t\) | 采样时间间隔 | 时间戳差       |
| \(p\)        | 设备笔压读数 | pressure       |
| \(s\)        | 笔画状态     | 落笔、抬笔信息 |

坐标使用统一书写区域尺度进行转换，时间统一为秒或毫秒中的一种；建议计算标准化输入时保留原始时间间隔、尺寸和压力统计数据，避免丢失你们想分析的信息。

对于无法提供某些通道的设备，应记录缺失情况，而不是把未知值直接当作真实的 0。

### 4.3 必须统一执行的预处理

1. 检查 JSON 或数据文件能否正确读取，保留数据来源、参与者及任务编号。
2. 验证时间戳顺序，处理重复时间戳、无效采样点和异常间隔。
3. 按笔画分段，保留相邻笔画之间的真实时间间隔。
4. 统一坐标方向和时间单位，保存书写区域原始尺寸。
5. 区分真实笔压读数、缺失压力及抬笔时的零压力。
6. 生成可变长度轨迹序列，在批量训练时使用 Padding Mask。
7. 独立保存有效心理问卷标签及其质量审查信息。

对于你们现有 MindTrace JSON，要特别注意之前发现的 `yNorm` 首点归一化差异，以及问卷存在的 `rapid_response_pattern`。这些都需要进入质量处理流程。

### 4.4 同时提取人工设计的书写特征

虽然我们将使用 BiGRU 学习特征，但仍然要保留一套可解释的人工特征。

建议第一版控制在约 20–30 维：

| 类别   | 优先提取指标                             |
| ------ | ---------------------------------------- |
| 速度   | 平均值、中位数、标准差、95 分位数        |
| 加速度 | 平均绝对加速度、波动                     |
| 笔压   | 平均值、标准差、10/90 分位数、压力范围   |
| 时间   | 有效书写时长、抬笔间隔、停顿占比         |
| 轨迹   | 总长度、平均笔画长度、直线度、方向变化   |
| 大小   | 书写包围盒宽高、宽高比、单位笔画空间范围 |
| 一致性 | 两遍标准抄写的速度、笔压与尺寸差异       |

书写方向角可以直接从相邻坐标推导：

\[ \theta_t=\operatorname{atan2}(\Delta y_t,\Delta x_t) \]

但要区分这与设备传感器报告的笔杆倾斜角。两者不是同一变量。

在公开数据与 MindTrace 共同训练的模型中，首先使用双方都能计算的共同特征；MindTrace 独有的可靠笔倾斜信息可以留作单独的消融实验。

本阶段完成标准： 三个数据源都能转换为统一轨迹输入；已获得的每份有效记录都能输出结构化特征，处理过程可重复，无异常数值和标签错配。

## 五、阶段 A：使用 CASIA-onDo 自监督预训练 BiGRU

第一阶段训练

不需要心理状态标签

### 5.1 这一阶段的目标

先让 BiGRU 学习如何表示正常的书写运动轨迹。

模型看到的是：

- 坐标如何随时间变化；
- 笔画如何连续运动；
- 书写速度如何变化；
- 压力如何在笔画内部变化；
- 不同笔画之间如何连接。

它并不知道任何参与者的心理状态。

因此，本阶段产生的是“预训练笔迹编码器”，不是心理状态预测模型。

### 5.2 采用什么自监督任务？

最终推荐：

Masked Trajectory Reconstruction（遮盖轨迹重建）

设计上参考 POSM 的部分笔画遮盖思想。POSM 在中文和英文在线笔迹的表示学习任务中报告了迁移学习收益，但下面是我们为 MindTrace 制定的工程实现，不是原论文代码的逐行复现。

BiGRU 的训练任务

根据未被遮盖的信息，预测中间缺失的坐标变化、时间间隔和笔压，并与原始数据比较，计算重建损失。

具体训练过程：

1. 从 CASIA-onDo 取出一段轨迹。
2. 随机遮盖约 15% 的有效采样点，以连续片段为主。
3. 把被遮盖通道替换为专用 Mask 值，并额外提供掩码标志。
4. 将序列送入 BiGRU。
5. 用重建头恢复被遮盖的 \(\Delta x,\Delta y,\Delta t,p\)。
6. 只在被遮盖且确实有有效测量的目标上计算损失，更新模型参数。

通过这种方式，模型不需要心理问卷标签，就能学习轨迹表征。

一个初始损失函数可以是：

\[ \mathcal L_{\text{pretrain}} = \sum_{c\in\{x,y,t,p\}} \lambda_c \operatorname{Huber}_{\mathcal M_c} (\hat X_c,X_c) \]

其中，\(\mathcal M_c\) 表示该通道中被遮盖且有效的采样点；\(\lambda_c\) 是各通道损失权重。

建议先把各连续通道按训练集统计量标准化，令权重都取 1，再根据实际误差分析决定是否需要调整。

### 5.3 固定初始模型配置

这是一组适合第一版研究的小模型参数，不是已经验证最优的超参数。

| 参数           | 初始值                  |
| -------------- | ----------------------- |
| 编码器         | BiGRU                   |
| GRU 层数       | 2                       |
| 单方向隐藏维度 | 64                      |
| 双向输出维度   | 128                     |
| Dropout        | 0.2                     |
| 轨迹片段长度   | 256 个采样点            |
| Batch Size     | 32                      |
| Optimizer      | AdamW                   |
| 初始学习率     | 0.001                   |
| 最大 Epoch     | 50                      |
| Early Stopping | 验证损失连续 7 轮无改善 |
| 随机种子       | 42                      |

长轨迹采用分段输入，每段保留来源和原始笔画信息。不要为了制造更多训练样本而把一个人的多个片段当成不同的独立参与者。

### 5.5 怎样判断预训练成功？

建议检查三方面：

| 指标         | 判断方法                                   |
| ------------ | ------------------------------------------ |
| 重建能力     | 测试集上 Masked MAE / Huber Loss           |
| 表征稳定性   | 同一轨迹的合理扰动前后，特征向量是否较稳定 |
| 下游迁移价值 | 在 EMOTHAW 上是否优于从零训练的同结构模型  |

第三项是最终判断预训练有没有价值的关键。

即使预训练损失明显下降，也只能说明模型学会了重建轨迹，不能证明它学会了预测心理状态。

### 6.1 明确训练目标

EMOTHAW 的标签来自 DASS，可以研究抑郁、焦虑、压力三个维度。

### 6.4 先冻结编码器，再尝试微调

实验 B1：冻结式迁移

实验 B2：局部微调

- 解冻 BiGRU 最后一层。

### 6.5 必须避免的一种数据泄漏

假设 EMOTHAW 的 129 名参与者每人有七个任务。

错误做法：

- 同一人的句子抄写进入训练集。
- 同一人的五边形绘图进入测试集。
- 模型识别出个人书写习惯。
- 得到看起来很高的准确率。

正确做法是：

以 participant_id 为最小独立划分单位。

推荐使用参与者级五折外层交叉验证，训练折内再进行三折模型选择；类别分布允许时采用分层分组策略。

EMOTHAW 监督训练的所有样本、特征标准化、类别权重、特征选择和超参数调整，都必须遵守这个划分。

### 6.6 减少与中文 MindTrace 的任务差异

这一点对于跨数据集迁移尤其重要。

EMOTHAW 有绘图、单词书写、句子书写等任务，而 MindTrace 主要包括中文句子抄写、自由书写和压力热身。

所以我们固定两种实验设置：

| 设置        | EMOTHAW 输入                                         | 目的                                        |
| ----------- | ---------------------------------------------------- | ------------------------------------------- |
| B-Main      | 仅使用可匹配的落笔书写任务和共同传感器特征           | 作为迁移到 MindTrace 的主模型               |
| B-Reference | 使用论文所需的书写与绘图信息，包括可用的悬空运动特征 | 对照公开研究，不直接作为 MindTrace 最终模型 |

这种安排可以减少一个问题：模型在公开数据中学会依赖悬空轨迹、特定绘图任务，迁移到 MindTrace 时却根本没有这些输入。

### 7.1 为什么不能直接加载阶段 B 的分类器？

因为阶段 B 预测的是 EMOTHAW 的 DASS 类别，而你们的 MindTrace 标签是 MRS-18。

因此，我们采用：

保留书写编码器、移除 DASS 分类头、重新训练 MRS-18 回归头。

阶段 B 训练好的 BiGRU 编码器

加载至 MindTrace 模型

保留轨迹编码参数，移除原 DASS 分类头

新的 MindTrace 回归头

输入：笔迹表示和共同统计特征

输出：MRS-18 参考指标

第一版固定预测：

\[ \hat y_{\mathrm{MT}} =f_{\theta}(X_{\mathrm{handwriting}}) \]

其中 \(y_{\mathrm{MT}}\) 是 `symptomSumS`，而不是直接诊断某种心理疾病。

### 7.2 MindTrace 的训练样本到底怎么算？

假设收集 20 人，每人三轮：

# 20

参与者

# 3

轮/人

# 60

完整测量记录上限

每份测量有多个书写任务，但这些任务共享同一轮问卷标签，不能当成多个独立的人。

因此，建议的训练粒度是每人每轮一个监督样本。

先分别对抄写任务提取特征，再把同轮的两个抄写任务聚合成一个表示。自由书写和压力热身则可作为辅助特征分支，在消融实验中单独验证是否有用。

需要特别防范一个问题：自由书写的长度和内容差异很大，可能导致模型主要根据写了多少字进行预测。第一版主模型建议优先使用重复的标准抄写任务。

### 7.3 采用什么验证方法？

主评估固定为：

Leave-One-Subject-Out（留一参与者交叉验证，LOSO）

假设所有 20 人都完成三轮有效采集：

| 部分     | 数据                        |
| -------- | --------------------------- |
| 训练集   | 19 人，最多 57 次测量       |
| 测试集   | 留出的 1 人，最多 3 次测量  |
| 重复次数 | 20 轮，每人轮流成为测试对象 |

训练参与者内部还需进行分组交叉验证来选择模型参数和 Early Stopping 时机，不得利用被留出的参与者调整模型。

尤其不能先把全部 60 份数据拿来做标准化或特征筛选，然后再交叉验证。

因为这样测试人的数据已经影响了模型处理过程，会产生泄漏。

### 7.4 三个月的数据除了训练，还能做什么？

你们最大的特点是同一人连续三个月的纵向记录。

建议额外研究：

\[ \Delta X_{i,t}=X_{i,t}-X_{i,1} \]

\[ \Delta y_{i,t}=y_{i,t}-y_{i,1} \]

例如：

- 第 2 个月是否比第 1 个月书写更慢？
- 笔压波动是否变大？
- 书写停顿是否增多？
- 这些变化是否与同期问卷分数变化有关？

这是个体内变化关联分析，应作为与新参与者泛化预测不同的研究任务来报告。

只有三个时间点，不能支持复杂的长期趋势建模，也不能证明某个笔迹变化是心理状态变化造成的。

### 7.5 如何判断 MindTrace 模型有实际价值？

因为 MRS-18 是连续分数，主指标采用：

| 指标                | 用途                         |
| ------------------- | ---------------------------- |
| MAE                 | 平均预测误差，主要指标       |
| RMSE                | 检查较大的预测偏差           |
| Spearman 相关       | 辅助判断预测排序             |
| 按参与者汇总的误差  | 观察是否只对少数人有效       |
| DummyRegressor 对照 | 判断模型是否优于简单均值预测 |

这里没有必要提前规定必须达到“90% 准确率”。

如果没有正式定义分类任务，回归分数本来就不应该直接用“准确率”评价。

对于仅有约 20 名参与者的数据，即便回归模型优于均值基线，也只能支持初步的探索性结论。

## 九、结果程序怎么接入？

到最终结果程序阶段，不建议把 BiGRU 的输出直接变成“心理疾病概率”。

应该让应用明确区分直接测得的数据和模型估计的数据。

建议接口输出类似下面的结构：

```
{
  "data_quality": {
    "handwriting": "usable",
    "questionnaire": "review_required"
  },
  "handwriting_features": {
    "mean_speed": 151.7,
    "mean_pressure": 0.3691,
    "pressure_std": 0.183
  },
  "questionnaire": {
    "instrument": "MINDTRACE_RECENT_STATE_18",
    "status": "needs_review"
  },
  "model": {
    "name": "MindTrace-BiGRU",
    "prediction_status": "not_available",
    "predicted_mrs_score": null
  }
}
```

这组笔迹特征取自你之前提供的样本抄写任务，问卷仍保留质量待复核状态。它不是模型已经完成预测的结果。

真正部署时应遵守：

- 数据质量不合格时，不生成心理预测。
- 模型尚未通过预设验证标准时，只显示测量与研究性分析。
- 不输出没有校准依据的“焦虑概率 85%”之类结论。
- 用户可以查看哪些结果来自问卷、哪些来自笔迹、哪些来自模型估计。
- 自由书写内容和心理数据应受到隐私保护，避免未经授权传给外部语言模型。

如果后来需要加入 Qwen 等 LLM，建议只让它基于经过审核的结构化数据生成解释报告，不让它重新猜测或篡改模型分数。

### 4. 实际编程应该按照什么顺序？

建议严格按照下面这个顺序，一次完成一个脚本，不要同时让代码 Agent 生成全部工程。

| 次序 | 首先实现的文件                     | 通过标准                             |
| ---- | ---------------------------------- | ------------------------------------ |
| 1    | `datasets/mindtrace.py`            | 正确读取你们已有 JSON                |
| 2    | `preprocessing/quality_control.py` | 识别无效轨迹和问卷质量标记           |
| 3    | `preprocessing/trajectory.py`      | 正确输出统一五通道序列               |
| 4    | `preprocessing/features.py`        | 正确计算速度、笔压、大小等           |
| 5    | `datasets/casia.py`                | CASIA 样本输出相同轨迹接口           |
| 6    | `datasets/emothaw.py`              | EMOTHAW 样本及标签正确对应           |
| 7    | `models/bigru_encoder.py`          | 测试数据能完成前向传播               |
| 8    | `training/pretrain.py`             | CASIA 的自监督训练可以运行           |
| 9    | `training/supervised.py`           | EMOTHAW 的监督训练可以运行           |
| 10   | `training/transfer.py`             | MindTrace 可以加载编码器并训练预测头 |
| 11   | `evaluation/cross_validation.py`   | 正确实现参与者隔离验证               |

另外，从第一个脚本开始就要建立必要的单元测试，特别是时间戳、反向计分、数据划分和输入维度的检查。

我不建议第一天就让 Codex 写出整个模型并直接开始训练。 更适合的是你们逐步实现、自己运行单元测试、观察每一步的输入输出，再进行下一阶段。这能有效避免模型看起来训练成功，实际上数据处理存在问题。

## 十二、哪些情况必须提前设定应对方案？

你说希望流程制定后不再修改，因此我把最容易遇到的情况及处理方式直接写进计划。

| 可能发生的问题               | 固定处理方式                                                 |
| ---------------------------- | ------------------------------------------------------------ |
| CASIA 数据集尚未审批完成     | 先开发 MindTrace 数据处理与基线，不阻塞其他任务              |
| EMOTHAW 完整轨迹无法获得     | 先做可获取的特征实验；无法训练公开监督模型时，如实记录缺失   |
| CASIA 预训练效果不佳         | 保留从零训练的对照，使用实际更优的编码器                     |
| EMOTHAW 分类结果不佳         | 排查参与者划分、任务差异、类别不平衡和数据质量；不随意更改标签 |
| CASIA → EMOTHAW 没有提升     | 将“预训练迁移无增益”作为实验结论                             |
| EMOTHAW → MindTrace 效果较差 | 保留传统特征基线与描述性统计，不强行输出个人心理预测         |
| MindTrace 不足 60 份有效记录 | 按真实样本数量报告，不用复制轨迹伪造独立样本                 |
| 设备差异明显                 | 保留设备信息，分析设备影响，必要时限制推断适用设备           |
| 心理问卷质量异常             | 暂停将相关记录用于监督训练，进入人工复核                     |

这里有一个底线：可以固定流程，不能提前固定实验结论。

即使最后发现迁移学习没有提升，也是一个完整的研究结果。你们应该证明自己做了哪些有效的检验，而不是为了项目演示追求一个未经验证的准确率。

## 最终：我建议你们正式采用的研究方案

## MindTrace-BiGRU：基于自监督预训练与跨数据集迁移的动态笔迹心理状态指标预测方法

建议用作项目模型研发任务的正式名称

整个项目围绕一个核心问题：

> 大规模在线笔迹数据上学习到的动态书写表示，能否通过少量心理问卷监督数据进行迁移，并提升对中文数字笔迹对应问卷指标的预测表现？

三套数据各自负责一个环节：

- CASIA-onDo： 学习书写运动规律。
- EMOTHAW： 学习与 DASS 心理问卷指标相关的预测任务。
- MindTrace： 适配自定义问卷并独立检验中文场景下的效果。

整个项目围绕 一个 BiGRU 编码器、两个不同目标的预测头、一套统一预处理系统、一个传统机器学习基线体系展开。

你们不需要继续寻找越来越大的语言模型，也不必再把 OnlineHTR 作为主线。

### 现在的第一件事

先完成第 4 章的数据工程，而不是立即开始训练。

具体来说，先使用你们已经有的 MindTrace JSON，实现统一轨迹转换和手工特征提取；与此同时申请两套公开数据，并固定正式采集协议。完成后，再按照 E1 基线 → CASIA 预训练 → EMOTHAW 监督训练 → MindTrace 迁移的顺序执行。

这样后面的每一个训练阶段都有明确的数据输入、模型输出和完成标准，能够从中期一直推进到结题，而不需要因为模型方向反复重新设计项目。
