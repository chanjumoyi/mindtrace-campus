# 开发 测试与发布

状态：已按立项报告对齐
最后更新：2026-10-12

首次拉取或为新电脑配置环境时，先完整阅读[新成员环境安装与项目测试指南](./setup-guide.md)。该指南列出了当前必需软件、VS Code 推荐插件、Docker 一键启动、本地开发方式、验收步骤和常见问题。

## 环境基线

- 前端：Vue 3、Vite、Node.js LTS。
- 后端：Python 3.12、FastAPI、SQLAlchemy。
- 数据库：MySQL 8；自动化测试可使用隔离的临时数据库。
- AI：DeepSeek 或兼容 LLM API；默认支持无密钥的 Mock 降级。
- 采集：浏览器 Canvas 与 Pointer Events。
- 部署：Docker Compose；生产配置通过部署环境注入。

开发环境采用最小拓扑 `frontend + api + mysql`，默认使用同步任务和本地对象存储适配器。进入集成或用户测试阶段后，增加与 API 同代码版本的 Worker、Redis Broker 和 S3 兼容对象存储；业务模块不得因拓扑切换而修改。

## 开发约定

- 前端统一通过 API 客户端访问 `/api/v1`。
- 后端按 API、service、model、schema 和 integration 分层。
- 新模块必须放入 `backend/app/modules/<module>`，并遵守路由、应用服务、领域规则、仓储和基础设施的依赖方向。
- 新代码必须遵守架构文档的文件职责和大小限制；不得继续把完整功能堆入 `App.vue`、根级 `models.py` 或根级 `schemas.py`。
- 数据库 Schema 使用迁移工具管理。
- Prompt、JSON Schema、特征和模型产物均记录版本。
- 外部 LLM、任务队列和对象存储只能通过公共端口及适配器访问。
- 研究脚本与线上服务分离，训练数据不进入应用镜像。

## 测试基线

- 后端：认证、数据归属、手账、情绪记录、危机安全分流和分析降级。
- 前端：路由、登录态、API 错误、核心表单、空状态和移动端布局。
- 算法：合成轨迹、异常输入、跨设备缺失字段、基线模型和输出范围。
- AI 安全：诊断越界、Prompt 注入、隐私泄漏、危机表达和上游失败。
- 端到端：注册登录、心情打卡、手账、对话、笔迹采集与数据删除。
- 发布前：格式检查、静态检查、单元测试、前端构建和依赖安全检查。

## 配置与安全

- 仓库只提交 `.env.example`，不提交 `.env`、数据库、模型密钥或参与者数据。
- 日志不得输出密码、令牌、AI 对话原文、手账、量表、图像或笔迹轨迹。
- 开发、测试和生产环境使用不同的数据库、密钥和对象存储。
- 外部 LLM 调用配置超时、有限重试和熔断，失败时不丢失本地分析结果。

## 发布门禁

- 主分支检查全部通过。
- 数据库迁移经过升级和回滚验证。
- 完成一次备份恢复演练。
- 高危安全问题清零，并确认隐私说明、求助路径和免责声明可见。

目录结构、配置命名、健康检查、质量门禁和 Definition of Done 以[系统架构说明](../02-architecture/README.md)为准。


## 移动书写画布的撤回与恢复

适用模块：`frontend/handwriting-collector-mobile`，抄写与自由书写页（压力热身页除外）。

- 双指轻点撤回一整笔，三指轻点恢复一整笔；画布上方的撤回/恢复按钮、手势、Ctrl/Cmd+Z 和 Ctrl+Y / Ctrl/Cmd+Shift+Z 共享同一套多级历史。工具栏显示实际操作结果，避免按钮落到画布下方不可见的位置。
- 手势范围覆盖当前书写页面的画布、边框和非交互空白区；按钮、输入框和链接不参与手指数统计。第三指先后落在画布边缘之外时，也要计入同一次手势，不能误当双指撤回。
- 同一次手势按最大同时接触数判定，等最后一指抬起后只执行一次操作。三指逐个抬起时不得降级成双指撤回；重新落下的接触点不得累计为额外手指。
- 每次手势独立选择事件来源；原生 TouchEvent 出现后只接管本次会话，不永久关闭后续 PointerEvent 回退。仅收到指针事件时保留 120 ms 的完成等待，让迟到的原生事件接管同一个笔迹快照，避免重复执行。
- 原生手指数同时参考开始、移动和结束事件的快照，结束时合并仍按住与刚抬起的触点，避免漏掉第三指的开始事件后误触撤回。原生输入接管后不再累加可能漏掉抬起事件的指针 ID，防止双指重新落下被误算为三指。
- 新的独立指针序列会先结算上一段待完成的手势，避免快速连续点击被合并。清空和组件卸载取消待完成操作。
- 捕获丢失（lostpointercapture）只表示事件接收目标变化，不能当成抬指、位移或取消，尤其是在仅有 PointerEvent 的 Windows 浏览器中。捕获丢失后由 window 监听实际的 pointerup/pointercancel，保证画布外抬指仍能收尾。pointercancel 不得否决随后完整到达的原生触摸；真正取消、滑动、长按和四指触摸不执行撤回或恢复。
- 手势预览点不进入最终采集结果；撤回/恢复重绘画布并重算质量指标。提交新笔迹或清空后，旧的恢复记录失效。

自动化验收：`npm run test:runtime -- tests/canvas-gestures.spec.ts --workers=1`。测试使用合成笔迹，覆盖真实浏览器多指输入、逐指抬起、事件缺失/交错、取消、多级历史、像素恢复与导出指标。构建验收使用 `npm run build`，同时检查受保护的移动运行时文件。

浏览器事件测试不能代替 Android 真机验收。设备上需检查双指撤回、三指恢复、快速连续操作、系统三指手势拦截以及按钮恢复；系统未交给页面的触摸仍须使用撤回/恢复按钮。

本地开发环境会发出不含笔迹坐标的 `writing-gesture-result` 调试事件，包含手指数、耗时、拒绝原因和历史数量，便于区分未收到三指、被判定为移动/超时、没有恢复历史与实际恢复成功；生产构建不包含该诊断。

### ty 分支的 Android 实机测试包

`ty` 的调试包版本为 `1.0.3-ty`（versionCode 4），应用名为“心迹书写采集 · ty”，包名为 `com.mindtrace.collector.ty`。它可以和原应用并存，拥有独立的本机数据；这次分支保存与打包不合并到其他分支。

使用 `npm run android:apk` 构建；APK 为本地调试签名测试包。Windows 中文工程目录若被 Android Gradle Plugin 拒绝，可在完成 `npm run android:sync` 后，于 `android/` 执行 `./gradlew.bat "-Pandroid.overridePathCheck=true" assembleDebug`。确认 APK 的版本、包名和签名后再交付。
