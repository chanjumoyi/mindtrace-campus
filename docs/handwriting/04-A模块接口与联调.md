# A 模块接口与联调说明

## 1. 当前闭环

角色 A 当前负责并可在本地独立验证的链路是：

```text
华为平板 + Pencil 采集
  -> 完整轨迹 JSON
  -> 数据质量检查
  -> 可解释特征提取
  -> 行为指标与客观观察
  -> 书籍假设引用
  -> HTTP API / 结果展示页
```

本链路不是心理诊断模型。现阶段的数据规模只适合验证设备、数据协议、特征、个人纵向实验和接口闭环。

## 2. 本地运行

先启动服务：

```powershell
Set-Location D:\project\mindLine
python local\ai-lab\handwriting\service\server.py --port 8091
```

电脑浏览器打开：

```text
http://127.0.0.1:8091/
```

选择采集器导出的轨迹 JSON，页面将展示：

- 数据质量和置信度；
- 笔划数、采样点、抬笔间隔、速度、压力等客观观察；
- 停顿、节律波动、设备压力三个透明指标；
- 《笔迹心理学》证据矩阵中的引用与使用边界；
- 当前结果的限制说明。

## 3. 给角色 C 的接口

- 健康检查：`GET /api/v1/health`
- 笔迹分析：`POST /api/v1/handwriting/analyze`
- OpenAPI：`contracts/openapi/handwriting-analysis.yaml`
- 输入 Schema：`contracts/schemas/handwriting-trace.schema.json`
- 输出 Schema：`contracts/schemas/handwriting-analysis-result.schema.json`

请求示例：

```json
{
  "requestId": "req-001",
  "trace": {
    "schemaVersion": "1.0.0",
    "sessionId": "session-001",
    "participantId": "anonymous-001",
    "task": {},
    "points": []
  }
}
```

实际请求必须传入采集器导出的完整 `trace`，不能再使用旧版 `strokes` 数组。

## 4. 模型训练边界

当前 Ridge 基线只用于检验数据管线是否可训练，不应包装成通用“大模型”。在继续拟合前至少需要：

1. 增加不同匿名参与者，而不是继续重复采集同一个人；
2. 每位参与者在固定设备和固定任务下完成多时点采集；
3. 使用独立量表或明确的自评作为标签，书籍文字只能形成待验证假设，不能直接生成真值标签；
4. 按参与者划分训练、验证、测试集，禁止同一人的记录跨集合泄漏；
5. 报告 MAE、基线对照、置信区间和失败样例，不只报告训练集拟合分数。
