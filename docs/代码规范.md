# 代码与目录规范

## 1. 目录职责

| 目录 | 允许内容 | 禁止内容 |
|---|---|---|
| `frontend/` | Vue 页面、组件、交互逻辑、公开静态资源 | API 密钥、诊断结论、真实参与者数据 |
| `backend/` | FastAPI 路由、业务服务、数据模型、安全规则 | 前端构建产物、研究原始数据、硬编码密钥 |
| `research/` | 可复现实验脚本、公开知识、Prompt、合成样例 | 未脱敏对话、笔迹、量表和身份信息 |
| `tests/` | API、算法和纯逻辑测试 | 依赖个人机器状态的测试数据 |
| `docs/` | 架构、需求、接口、安全与研究流程文档 | 个人联系方式和未公开材料 |

运行代码与研究资产必须分离：产品运行时不能隐式依赖 `research/` 中的临时文件；需要上线的模型或规则应经过版本化、审核和显式配置。

## 2. 格式与命名

- 全仓库使用 UTF-8、LF 换行、文件末尾保留换行；基础规则见 `.editorconfig`。
- Python 使用 4 空格、100 字符行宽、完整类型标注；模块和函数使用 `snake_case`，类使用 `PascalCase`。
- Vue/JavaScript 使用 2 空格、单引号、无分号；组件使用 `PascalCase.vue`，普通模块使用 `kebab-case.js` 或现有约定。
- API 路径使用小写复数名词；Pydantic 请求/响应模型不得直接复用数据库模型。
- 配置只从环境变量或配置文件读取；示例值放入 `.env.example`，真实密钥不得提交。

Python 静态规则记录在 `pyproject.toml`。前端在引入 ESLint/Prettier 前，至少执行构建与 `node --check`，并保持 Vue 模板为多行可读格式。

## 3. 代码边界

- 路由层只做输入校验、鉴权和响应编排；算法、LLM 调用与业务规则放在 `services/`。
- 数据写入必须经过 Schema 校验，并预留用户归属、授权、审计和删除能力。
- AI 输出必须携带非诊断声明；危机信号应进入专门安全流程，不得只依赖模型自由生成。
- 笔迹、房树人和沙盘只能输出可观察事实、限制说明和探索性问题，不能映射疾病或人格结论。
- 新增功能时同步更新 `docs/需求清单.md`、接口文档和对应测试。

## 4. 提交前检查

```powershell
python -m pytest
python -m compileall backend research tests
node --check frontend/src/api.js
node tests/test_pointer_normalization.cjs
Set-Location frontend
npm run build
```

还需执行 `git diff --check`，确认没有密钥、个人信息、数据库、缓存、模型产物和真实研究数据进入提交。
