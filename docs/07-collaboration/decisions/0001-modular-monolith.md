# ADR-0001 采用研究型模块化单体架构

状态：已接受

日期：2026-10-11

决策人：项目团队

## 背景

心迹AI由三人团队在一年大创周期内完成，需要同时交付可运行 Web 平台、AI 与笔迹研究功能、用户测试和结项材料。项目包含敏感数据、外部 LLM、笔迹与绘画文件以及耗时分析任务，但当前用户规模和团队规模不足以支撑微服务带来的部署和治理成本。

## 决策

项目采用研究型模块化单体：

- 一个 Vue 3 前端应用。
- 一个 FastAPI 后端代码库和 API 部署单元。
- 可选 Worker 与 API 复用同一代码和模块。
- MySQL 保存结构化数据，对象存储保存大文件和原始数据。
- 通过稳定端口隔离 LLM、任务队列和对象存储。
- 开发阶段使用 Inline Task 与本地文件适配器，集成阶段切换 Celery/Redis 与 S3 兼容存储。
- 离线研究代码与线上服务隔离。

模块边界、数据所有权、任务状态和安全规则以 `docs/02-architecture/README.md` 为准。

## 备选方案

### 轻量单体

优点是开发和部署最快；缺点是容易把路由、数据库、算法和外部服务混合，后续接入异步分析和研究导出时需要较大重构。

### 微服务

优点是独立部署和扩缩容；缺点是需要额外处理服务发现、跨服务认证、分布式追踪、数据一致性和多环境部署，不适合当前团队与周期。

## 影响

正面影响：

- 部署和调试保持简单。
- 成员可按模块并行开发。
- 基础设施可以通过适配器替换，不改业务逻辑。
- 数据归属和研究边界更清晰。

代价与风险：

- 团队必须通过代码评审维护模块边界。
- 单个代码库的错误可能影响整个 API，需要完善测试和降级。
- Worker 虽复用代码，仍需保证版本和数据库迁移一致。

## 后续行动

1. 按架构文档建立目标目录和公共端口。
2. 引入 Alembic、统一错误、请求 ID 和结构化日志。
3. 优先完成身份、授权和数据归属，再扩展研究模块。
4. 只有满足架构文档中的触发条件后才启用 Redis、Worker 和 S3 适配器。
